# Завантаження проєкту (Етап 4) — простими словами

Технічні файли: [`src/app/projects/new/`](../src/app/projects/new/) (форма),
[`src/lib/validation/architecture-dna.ts`](../src/lib/validation/architecture-dna.ts)
(поля для архітектури), [`src/lib/storage.ts`](../src/lib/storage.ts)
(куди фізично зберігаються файли). Тут — що це означає для продукту, без
коду.

## Хто може завантажувати

Тільки **Творець** з основним напрямом "Архітектура" (інші чотири напрями —
коли дійде черга масштабувати рушій, CLAUDE.md, план MVP). Отримувач сюди
взагалі не потрапляє — не той функціонал для його ролі.

## Поля форми

**Загальне**
- Назва проєкту — обов'язково
- Опис — до 1000 символів, необов'язково
- Хештеги — через кому, необов'язково. Розширюють пошук і всередині
  платформи, і в Google (потрапляють у службові теги сторінки проєкту)

**Про об'єкт**
- Тип об'єкта — один із 11: житлова, громадська, промислова, ландшафтна,
  містобудівна, **комерційна нерухомість**, **мала архітектурна форма**,
  **вуличні меблі**, **вуличний арт-об'єкт**, **монумент**, **фонтан**
  (жирним — додано за вашим запитом)
- Стиль архітектури — 25 історичних/сучасних стилів з української
  Вікіпедії (від романського до деконструктивізму, хай-теку, кінетичної
  архітектури) плюс три службові варіанти: **біонічна архітектура**,
  **власний стиль**, **стиль не визначено** — щоб поле завжди можна було
  заповнити, навіть якщо жоден зі стилів не підходить
- Підтип (вільний текст), загальна площа, площа ділянки (**позначена як
  "бажано"**, не обов'язкова), поверховість, кількість юнітів, рік, тип
  роботи (навчальний/конкурсний/дипломний/концепт), використаний софт

**Ціна** — два незалежних поля, обидва необов'язкові:
- Ціна — базова вартість проєкту як є
- Авторське право на доопрацювання — окрема сума за право розвинути
  ескіз далі (якщо покупець хоче не готовий проєкт, а основу для власної
  розробки)

Якщо обидва поля порожні — проєкт показується як "лише портфоліо".

**Файли** — рендери, плани, розрізи, 3D-модель, документи. Ліміт — **21 МБ
на файл**. Під час вибору файлу людина одразу бачить його мініатюру
(зображення) або значок з назвою (інші формати) — це і є "попередній
перегляд"; "основний перегляд" — уже на сторінці самого проєкту після
публікації, у повному розмірі.

## Куди фізично зберігаються файли

Поки що — прямо на диску сервера, у папці `public/uploads`. Це свідомий
тимчасовий вибір: працює одразу, без додаткових акаунтів і оплати за
хмарне сховище, і достатньо для закритого бета-тесту (Етап 8). Мінус:
такий підхід не підійде, якщо в майбутньому оберемо хостинг, де диск
"не постійний" (наприклад Vercel) — там знадобиться підключити хмарне
сховище (S3-сумісне, наприклад Cloudflare R2). Коли дійде до цього рішення —
міняється тільки один файл коду (`src/lib/storage.ts`), форма й решта
коду цього навіть не відчують.
