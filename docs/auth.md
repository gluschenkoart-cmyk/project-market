# Автентифікація (Етап 3) — простими словами

## Перелік полів

**Збирається завжди** (при email-реєстрації — одразу; при вході через
Google/Apple — одразу після першого входу, бо звідти цих даних узяти
нема звідки):

| Поле | Обов'язкове | Коментар |
|---|---|---|
| Email | так | приходить від Google/Apple автоматично |
| Пароль | лише для email-входу | не питаємо при Google/Apple |
| Повне ім'я | так | для Google/Apple попередньо заповнюємо тим, що там вказано, — людина підтверджує або виправляє |
| Телефон | **так, завжди** | навіть при вході через Google/Apple — за вашою вимогою |
| Навчальний заклад | так | вільний текст — приймає й школи гейм-дизайну, курси тощо |
| Факультет | ні | необов'язково |
| Підтвердження авторського права | так | чекбокс |
| **Роль** | так | **Творець** або **Отримувач** — див. нижче |
| **Основний напрям** | лише для Творця | один з пʼяти: Архітектура, Образотворче мистецтво, Скульптура, Дизайн, Цифрове мистецтво/3D/Анімація |

## Дві ролі

- **Творець** — показує, архівує й продає власні проєкти
- **Отримувач** — шукає й купує/ліцензує готові проєкти (архбюро,
  девелопери, галереї — те, що в стратегічних документах називалось
  "Buyers")

Роль обирається одразу після першого входу (перш ніж потрапити в
профіль) — двома великими картками, не випадаючим списком. Для Творця
одразу за цим — вибір напряму, теж картками. Наразі форма завантаження
проєкту (Етап 4) працюватиме тільки для напряму "Архітектура" — інші
чотири можна обрати вже зараз, завантаження для них зʼявиться пізніше.

## Як увійти

Три способи, всі ведуть в один і той самий акаунт:
1. **Google** — один клік, дані підтягуються з акаунту Google
2. **Apple** — один клік, так само
3. **Email + пароль** — для тих, хто не хоче прив'язувати такий акаунт

Виняток — двоє адміністраторів платформи (`ADMIN_EMAILS`, `docs/admin.md`):
для їхніх адрес спосіб 3 навмисно вимкнено з міркувань безпеки, вхід
лише через Google чи Apple.

## Що потрібно від вас, щоб Google/Apple запрацювали

Обидва — не автоматичні, платформи вимагають, щоб власник продукту сам
зареєстрував застосунок:

**Google (безкоштовно, ~10 хвилин):**
1. [console.cloud.google.com](https://console.cloud.google.com) → створити проєкт
2. "OAuth consent screen" → заповнити назву застосунку
3. "Credentials" → "Create OAuth client ID" → тип "Web application"
4. Скопіювати Client ID і Client Secret — надішлете мені, я додам у налаштування

**Apple (потребує платного Apple Developer Program, $99/рік):**
Процес довший (Team ID, Services ID, приватний ключ) — має сенс робити
це ближче до реального запуску, а не зараз. Google тим часом уже
покриває більшість людей, які хочуть швидкий вхід без пароля.

## Що ще не перевірено наживо

Через мережеві обмеження середовища (npm) і відсутність підключеної бази
даних я поки не можу сам пройти весь шлях і натиснути кнопки, щоб
перевірити на практиці. Логіка написана за стандартним, широко
перевіреним підходом (Auth.js) — "чесна" перевірка відбудеться разом із
першим реальним запуском.
