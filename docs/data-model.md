# Ядро даних (Етап 2) — простими словами

Технічний файл схеми: [`prisma/schema.prisma`](../prisma/schema.prisma).
Тут — що саме він означає для продукту.

## Що система тепер "знає"

**Користувач** — коли хтось реєструється, ми зберігаємо: повне ім'я,
телефон (обов'язково, незалежно від способу входу), виш (вільний текст —
приймає не лише університети, а й школи гейм-дизайну, курси тощо),
факультет, і чи підтвердив він відповідальність за авторське право. Це
саме ті поля, що описані в `CLAUDE.md`. Додатково (Етап 6, необов'язково) —
Telegram і WhatsApp, для тих, хто оплатив перегляд контактів.

Кожен користувач — **Творець** або **Отримувач** (обирає при першому
вході, детальніше — `docs/auth.md`). Творець додатково вказує свій
основний напрям — один із пʼяти (Архітектура, Образотворче мистецтво,
Скульптура, Дизайн, Цифрове мистецтво/3D/Анімація).

**Проєкт** — картка проєкту знає:
- хто автор, у якій вертикалі (зараз тільки "Архітектура", інші чотири вже
  передбачені в системі — додати їх пізніше не означає все переробляти)
- назву, опис (до 1000 символів), хештеги (для пошуку на платформі й у
  Google), статус (Academic → Concept → For Sale → Sold/Licensed →
  Under Development → Built → Archived)
- дві незалежні ціни — або їх відсутність, що означає "лише портфоліо":
  базову ціну проєкту, і окремо — суму за право доопрацювати/розвинути
  ескіз далі (можна вказати одну, обидві або жодну)
- "Project DNA" для архітектури (повний перелік полів і опцій — простими
  словами в [`docs/project-upload.md`](./project-upload.md)): тип обʼєкта
  (11 варіантів, від житлової до фонтану й монумента), стиль архітектури
  (25 варіантів + "власний стиль"/"не визначено"), площа (загальна і,
  бажано, площа ділянки), поверховість, рік, походження роботи (навчальна/
  конкурсна/дипломна/концепт), використаний софт
- файли — рендери, плани, розрізи, 3D-модель, документи; до 21 МБ на файл

## Чому "Project DNA" зберігається окремо від решти

Поля для архітектури (площа, поверховість) не мають сенсу для скульптури
(висота, вага, наклад). Замість того, щоб з першого дня переробляти базу
даних під усі пʼять вертикалей одразу, ми тримаємо ці специфічні поля в
одному гнучкому "контейнері" на проєкті. Коли дійде черга до наступної
вертикалі — додамо нову форму для неї, а не будемо чіпати те, що вже
працює для архітектури.

**Обране** (Етап 6) — окремий, простий список: хто яких проєкти зберіг
собі. Доступно і Творцю, і Отримувачу.

**Оплата за перегляд контактів** (Етап 6) — окремий запис на кожну пару
"хто дивиться + проєкт": скільки заплатив, через якого провайдера
(LiqPay або тестовий режим), чи оплата пройшла. Один успішний запис —
контакти цього проєкту відкриті для цієї людини назавжди. Детальніше,
простими словами — [`docs/payments.md`](./payments.md).

## Що ще не готово

- Реальна база даних ще не підключена (це наступний практичний крок —
  оберу безкоштовний хостинг для PostgreSQL і підключу)
- Файли проєктів поки зберігаються прямо на диску сервера, не в хмарному
  сховищі — працює для беторестування, підключення хмари (S3/R2) —
  окреме питання перед публічним запуском (деталі — `docs/project-upload.md`)
- Справжні платежі LiqPay — код готовий (Етап 6), чекає на реальні ключі
  від вас (`docs/payments.md`)

Приклад "посівного" проєкту в `prisma/seed.ts` — це дипломна робота Марії
з ваших документів (персона автора №1), для перевірки, що все узгоджено.
